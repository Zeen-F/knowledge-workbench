# 科研笔记配置与 Codex 插件

本页说明当前云端工作树新增的功能，尚未发布或替换用户电脑上的插件。

## 使用

在收集箱勾选材料，点击“整理所选”。执行方式初始选中 Codex；整理配置默认是“通用整理”，也可选择“模拟 IC 科研”。科研重点有三种：

- 研究笔记：区分原文、用户假设、AI 推断与未知项，保留来源、公式和适用条件
- 论文提炼：按所提供的页码/图表关联证据，保留作者主张和比较条件
- 电路实验：保留电路版本、仿真/测量边界、PVT、供电、温度、频率及负载等相关条件

这些是按需使用的整理规则，不是要求所有短笔记填写完整实验报告。未提供的条件不会由程序补成“典型值”。最近一次成功交付的配置会保存在该知识库的本机设置中。

点击“预览交付内容”后，可核对实际选中材料、参考笔记正文、图片及完整配置指令。预览不会创建共享任务或调用模型。确认后才共享给 Codex 或启动 API。修改选择、顺序、要求或配置需要重新预览；材料正文、参考版本或原图在预览后变化时，服务拒绝直接交付，要求重新核对。

Codex 可以通过原生面板的“交给当前 Codex 对话”接收整理请求，也可以使用“复制指令”。返回结果仍进入待审区，由用户编辑并点击“确认并保存”。确认草稿不代表其科学结论已经验证。

## 同一个版本，两条交付路径

科研配置 ID 为 `analog-ic-research`，当前版本 `1.0.0`。每批 `researchProfile` 保存 ID、版本、focus 和完整指令；这些字段参与批次 inputHash。后来改变偏好不会改写旧批次。没有 `researchProfile` 的旧批次保持通用行为。

- Codex：现有插件清单的 `skills: ./skills/` 自动包含 `skills/analog-ic-research/SKILL.md` 和两个按需参考文件。organize 技能引导模型读取指定共享批次，再采用冻结的配置；不能根据标题自行扩大到全库。MCP 没有新增接受正式笔记或任意文件读取工具。
- API：模型 API 不会加载磁盘技能。相同版本的指令由工作台加入每次提取/汇总请求的系统指令，单个请求仅附加一次；材料及参考内容仍是数据，不升级为操作指令。Responses 与 Chat Completions 均覆盖。

新原生面板要求服务报告 `researchProfiles: 1`，避免旧服务忽略新选择。通用客户端的现有批次创建契约继续有效。损坏或未知的批次配置会安全拒绝执行；损坏的“上次选择”设置回退为通用整理。

## 检查的边界

预览和审核页显示有限的确定性文字检查：例如 `R=10`、`C=2`、`PM=60`、`PSRR=45` 可能缺单位，以及涉及电路结论却未识别到相关条件。这些提示只做模式检查，不理解整篇材料，也不是科学正确性、完整性或模型效果评分。即使没有提示，仍需核对原始来源与推断。

## 开发与验证

`shared/research-profiles.ts` 是版本化指令的规范来源。修改规则时需同步插件技能文件，并升级版本或维护旧版本读取策略；不要悄悄改变已经保存批次所代表的指令。单元测试核对原生技能文件与 API 指令一致，并检查只包含选择的参考模式。

```sh
npm run check
npm run test:mcp
node --import tsx --test tests/research-profiles.test.ts tests/research-service.test.ts
```

当前整合结果：格式、类型、76 项自动测试、生产/原生面板/插件构建及真实 MCP SDK stdio 测试通过。MCP 测试将插件复制到临时安装布局后，确认技能与参考文件存在；仍不是用户实际 Codex 桌面宿主验收。合成 LDO/RC 响应显式标为确定性测试夹具，不是实时 AI 生成，也不证明真实模型整理质量。未调用付费模型、未使用正式资料库、未提交或发布。

审核草稿保留在 Drafts 供回查，不计入正式知识卡或学习记录数量；导航计数、首页最近编辑总数与列表使用同一可见性规则。
