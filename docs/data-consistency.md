# 数据一致性与恢复约定

正式笔记、材料、审核决定和附件保存到 Obsidian Vault。SQLite 是可重建的索引与任务工作状态；批次输入、模型原始响应和提交进度位于库外应用目录。采集、写作及人工审核不依赖模型。

## 来源身份

接受草稿时重新扫描 Vault，用批次快照中的 `kb_source.id` 解析当前唯一来源文件。移动或重命名后写入现路径；缺失、重复身份或读取不完整会阻止接受，保留草稿。生成时的 ID、路径、版本、来源描述和文本保存在正式笔记的 `kb_source_snapshots`，批次快照不修改。不会用标题相似或旧路径推测来源。

## 批量结果与提交恢复

模型汇总首先持久化原始响应，再校验全部草稿并保存带输入版本及内容哈希的提交记录。逐份提交使用稳定请求标识和稳定文件身份；每次提交后记录进度。中断、落盘失败或进程重启后复用原结果并续写，已经保存的草稿不重复生成。文件已创建、SQLite 尚未插入的情况通过精确提交记录恢复。

校验失败的提交记录阻止自动继续。已存在草稿但原结果不可用时，不重新调用模型填补。模型格式错误且尚未提交任何草稿时允许重新汇总。响应尚未成功持久化前发生的进程崩溃，无法保证提供方恰好执行一次；这与已持久化结果的提交恢复是不同边界。

## Markdown 与 SQLite 的权威关系

- Markdown 的 `kb_review_state` 决定 pending、rejected 或 accepted。读取与重建时核对草稿身份和文件版本，再条件更新 SQLite 的审核缓存；外部改为 rejected 后不能继续接受。
- SQLite 的 jobs/job_items 决定执行、暂停和重试进度。重建审核索引不会改写运行中的任务状态。启动时中断的 running 任务转 paused。
- 接受期间预留草稿，拒绝并发接受、编辑、退回及重新定基；重建跳过这份在途草稿。目标保存和审核状态落盘各自检查版本。
- 接受写入过程中若外部修改审核文件，保留外部文件及接受恢复记录并报告冲突。目标可能已经写入；不得将这个阶段的失败误解为完全没有写入。
- 修订普通笔记保留原 ID、自定义属性、既有来源和待核对项；接受后为 working，canonical 提升仍需独立人工决定。

## 输入恢复与入口能力

收集箱输入按 Vault 保存独立恢复草稿；审核编辑按 Vault 与草稿 ID 保存。未保存时关闭/刷新有保护，界面区分本机恢复与正式保存。旧请求完成只能确认对应输入版本，不清空之后的输入。想法保存带请求标识，回执丢失后重复提交不会创建第二份材料。

浏览器恢复存储不可用时，输入在当前窗口内继续保留并显示提醒；不能据此承诺浏览器清理、隐私模式退出或存储损坏后的恢复。

服务通过 capabilities 提供截图、选库、密钥加密和插件准备能力。浏览器可连接有桌面能力的本机服务；纯浏览器服务提前禁用不支持的入口。系统加密能力由 Electron 实际查询。

笔记打开、搜索、关联读取及后台刷新均忽略过期响应。关联按解析后的目标聚合多种来源；图片显示说明并可查看原 SHA-256。

## 本地验证

```powershell
npm.cmd run check
npm.cmd run test:mcp
npm.cmd run test:reliability-ui
npm.cmd run test:ui
npm.cmd run test:paperdesk -- <Paperdesk源码目录>
npm.cmd run test:capture
npm.cmd run test:codex-host
```

`check` 包含全源码格式检查、TypeScript、全部单元/服务回归及构建。新增浏览器回归使用现有 Edge，可通过 `KWB_TEST_BROWSER` 选择已安装浏览器；其他脚本沿用仓库约定。测试使用临时合成资料并关闭本次创建的服务。`npm.cmd run demo` 使用独立临时 Vault，仅监听 loopback，退出时清理；需先构建，不读取个人 profile。

本轮未接收成功的云端补丁不视为已应用。运行日志、截图和本地差异交付另行记录；真实模型、个人库、安装器、远端 CI 与发布不从这些结果推定。
